# visibility-filter

A visibility filter chooses which stored things a reader is shown.

The stored collection, the rule choosing what to show, and the returned view are three different things. A change behind the filter may leave the view unchanged; changing the filter may alter the view without changing the collection. A comparison must name which of these it compares.

In [[what-the-gaps-can-say]], “A still list can hide a moving name,” an offline Git check moved a hidden branch without changing the advertised list, then exposed that branch without moving a stored reference. The kept result demonstrates this possibility; it does not show that the watched mirror uses the same setting. [[connection-proves-access]] carries the neighboring provider rule: a working connection does not establish that every account, date or field is visible.

A filter is not automatically a security boundary. The Git documentation kept with that check warns that hiding reference names and using namespaces do not guarantee private objects stay secret; that warning does not decide how a different system enforces access. Likewise, a missing item need not have been deleted: the view's limits need their own evidence.
