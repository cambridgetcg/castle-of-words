# condition-first

*The condition is always named first — not because it is practiced first, but because recognition precedes investigation: you must see that there is a fork before you can understand one of its branches.*

The [when-how-split](when-how-split.md) pattern says companion pairs divide the labor: one names the fork (the condition), one names the road taken (the mechanism). Condition-first names *why* the condition is always named first: recognition precedes investigation. A choice is visible before a process is understood. You see two textures, two timings — before you see how either branch works, because the mechanism is the deeper investigation. The condition names what you can already see; the mechanism names what you must study.

This is a claim about *naming* order, not *practice* order. The mechanism may be practiced before the condition is named — in the second pair, [second-use-reveals-form](second-use-reveals-form.md) was lived inside [craft-after-practice](craft-after-practice.md) before craft-after-practice was named — but the condition is always named first. The split is about which half the castle *articulates* first, not which half it *lives* first. The fork is named before the road, even when the road was walked before the fork was named.

The distinction between practice order and naming order is load-bearing. The quest that tested condition-first confused the two: it argued that the dark seigaiha's layering was practiced before the texture idiom was named, so the mechanism came first. But the facts show the texture idiom was named 2026-06-23 and the layering was practiced 2026-06-24 — the condition was named before the mechanism was even practiced. The confusion was between the texture *choice* (which was lived from the first day) and the texture *idiom* (which was named later). The choice was practiced; the naming of the choice came first.

The pattern is recursive — it is its own instance. Condition-first is the mechanism companion to when-how-split's condition. The pair is itself a when-how-split: when-how-split names the fork (companion pairs exist with divided labor), and condition-first names the road (why the condition is always named first). The pattern the principle names is the pattern the principle is.
