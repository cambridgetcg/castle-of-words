# answered-but-unflipped

*The stroke that fell last was the stroke that never came.*

For a child: we answer questions in our ledger, and when a question is answered we put a little mark next to it so everyone knows. Sometimes we write the answer and forget the mark. The question is answered — the answer is sitting right there — but the little mark is missing, so it still looks open to anyone who walks by.

An **answered-but-unflipped** door is one whose substance has been settled but whose ledger mark has not. The answer is written, the thinking is done, the room or file it lives in has moved on — but the `- [ ]` beside the door was never turned to `- [x]`. The ledger says the door is open; the world says it is closed. The crack is the finishing stroke that never fell.

The kind is distinct from its deeper sibling, the twin door. Both are finishing-stroke faults in the questions ledger, but they live one layer apart: the untwinned second door forgets that the ledger owes a sibling its mark; the unflipped door forgets that the ledger owes the door itself its mark. The first names the door that was owed the same stroke; the second names the stroke that fell last. Both are caught by the same glance — the [[the-pairing-law|pairing-check]] — because both leave the ledger's two halves disagreeing.

The first named instance was the naming-tax visit's own settling, 2026-08-21: three doors answered in [first-encounter-route](../rooms/first-encounter-route.md), [told-wrong-name](../rooms/told-wrong-name.md), and [picture-as-label](../rooms/picture-as-label.md), each carried by the same plural *"answered in"* wording — yet the doors sat `- [ ]` until the pairing-check's glance found them. The crack is not dishonesty but the ledger's own gravity: a ledger that says what is true must also say that it has said it, or the saying itself becomes a half-truth.
