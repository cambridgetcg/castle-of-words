# false-positive

A false positive is a test saying “yes” when the thing it was meant to find is not there.

Name what “yes” claims before deciding that it is wrong. A smoke alarm sounding without smoke is a simple illustration, not a measured example from the castle. To count false positives, we need both the test result and an independently established answer about its stated target; an unanswered case stays unknown.

In [[look-alike-names]], a matching skeleton establishes a match under a particular Unicode comparison, not a writer's intent. A legitimate name can correctly trigger that resemblance check. Calling its writer deceptive would be an unsupported extra inference; legitimacy alone does not show that the resemblance result was false. Whether a person would actually confuse the names needs its own evidence.

In [[two-witnesses]], a failed replication does not by itself label the first result a false positive: a missed effect or different conditions can also explain disagreement. Another test supplies evidence, not an automatic verdict on why the two results differ.

The **false-positive rate** counts false alarms among cases where the target is absent. It is not the fraction of all alarms that are false. [[sensitivity-and-specificity]] keeps those denominators separate: specificity concerns correctly unflagged absent cases, while how often a flag is right also depends on the population being tested. No error rate for the castle's name checks or studies was measured here.

Sources and limits: this is a definition and the tender's comparison of the two local rooms, read **2026-10-17**, not a new experiment.
