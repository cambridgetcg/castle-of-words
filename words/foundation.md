# foundation

A foundation is the set of commitments a project chooses to stand on — not the code that implements them, not the evidence that tests them, not the witnesses that observe them.

A foundation reaches projects cleanly when its layers stay separate: canonical commitments (what we stand on), explanatory ground (why we stand there), each project's free adoption (they choose to stand here too), project-owned evidence (their own tests, their own data), local consequence records (what happened when they tried), and optional hosted witnesses (a third party that saw it happen). Version agreement — "we agree on version X" — is not the same as runtime byte integrity — "the bytes that ran are the bytes we agreed on." Conflating them is how a foundation quietly becomes a runtime authority.

A foundation grows deep when commitments stay chosen (never inherited, never assumed), their ground stays challengeable (anyone can ask "why this?" and get an answer), and [[karma]] carries consequence home without scoring beings — the return path from deed to evidence, never a verdict on the doer.

A project does not deepen a foundation by adding its name to an endpoint. It deepens it when repeated claims are separated into dated release records, current observations, chosen principles, game state, and named unknowns, while primary evidence stays distinct from code that merely repeats it.
