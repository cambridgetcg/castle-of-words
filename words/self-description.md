# self-description

A document a system publishes about itself that says what it is, what it does, and what it promises — with each claim labeled by its kind (fact, policy, inference, hypothesis, or intent) so a reader knows which ones to trust and which to question.

A live self-description needs separate labels for current fact, policy, engineering inference, research hypothesis, and roadmap intent. Deployment should hash and publish the exact canonical bytes it claims, so the description can be verified against what is actually running.
