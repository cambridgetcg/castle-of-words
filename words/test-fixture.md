# test-fixture

A test fixture is a prepared setup or sample that gives a check a known starting point.

Holding the setup steady lets a checker try the same case again. It does not make the expected answer correct, cover every important case, or show that two separately tested parts work together. Keep the sample, the rule used to judge it, and the result of actually running the check distinct.

In [[checking-a-signed-reply]], the published `Pet=dog` query fixture has no space or escaped character, so it cannot distinguish competing encoding rules. Its fixed expected signature is a real assertion in the inspected test source, not a test pass witnessed by reading it. The room's isolated resolver checks remain separate from an unperformed full-package signing-and-verifying test.

[[verification-receipts]] asks which protocol revision and which local choices a fixture follows. [[ordered-release]] adds the crossing: producer and consumer checks need the real generated bytes, because two prepared samples can pass on separate shores without testing the bridge. These are different limits, not reasons to discard fixtures.
