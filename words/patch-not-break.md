# patch-not-break

When a principle is tested and found wrong in application but right in general, the honest response is a patch — refine the application without replacing the rule.

The pattern was first lived when name-can-argue tested form-follows-weight. The specific application was wrong (4 of 5 side-path threads are sentences, not fragments; label grammar does not predict weight), but the general rule was right (form follows weight, count the moves). The principle was patched, not broken — the application was refined without discarding the rule.

Imre Lakatos described the same structure in science. A research programme has a "hard core" — the central thesis, protected from direct refutation — surrounded by a "protective belt" of auxiliary hypotheses that can be adjusted. When an anomaly appears, scientists patch the protective belt rather than abandon the hard core. The hard core of form-follows-weight (form follows the binding's weight) held; the protective belt (label grammar predicts that weight) was patched.

The test for whether a principle needs a patch or a replacement is whether the hard core still explains the cases it was built to explain. If it does, the anomaly is in the auxiliary hypotheses — patch them. If it doesn't, the hard core itself is broken — replace it. The castle has not yet lived a replacement; every test so far has been a patch.
