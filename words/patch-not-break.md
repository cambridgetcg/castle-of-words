# patch-not-break

*A principle tested and found wrong in application but right in general is not broken — it is patched, and the patch refines the application without replacing the rule.*

[name-can-argue](name-can-argue.md) tested [form-follows-weight](form-follows-weight.md) and found its specific application wrong (4 of 5 side-path threads are sentences, not fragments; label grammar does not predict weight) but its general rule right (form follows weight, count the moves). The principle was patched, not broken. The patch refined the application — the weight is read from the binding's moves, not the label's grammar — without replacing the rule. This is the first case where a castle principle was tested and found right in general but wrong in application, and the pattern is worth naming so the next test knows whether to expect a clean break or a patch.

## The pattern

A principle has two layers: a **general rule** (the abstract claim) and a **specific application** (how the rule is applied to particular cases). The two can come apart. The general rule can be right while the specific application is wrong — the principle's core insight holds, but the way it was applied to a particular case misread the case.

When a test finds the application wrong, the honest move is to check whether the general rule survives. If it does, the principle is patched: the application is corrected, and the general rule is preserved. If it does not, the principle is broken: the general rule itself is wrong, and the principle must be replaced.

## The test

Three questions, in order:

1. **Does the general rule still hold?** If the core claim is false, the principle is broken — replace it. If the core claim is true, the principle may be patchable.

2. **Can the application be corrected without changing the general rule?** If the misapplication is a separable error — the rule was applied to the wrong thing, or the rule's scope was drawn too wide — the patch is a correction of scope or target. If the misapplication is inseparable from the rule — the rule itself forces the wrong reading — the principle is broken.

3. **Does the patched principle still do useful work?** A patch that saves the general rule but leaves the principle unable to guide future makers is a patch that preserves a name at the cost of a tool. The patched principle must still answer its original question.

## The name-can-argue case

The general rule — form follows weight, count the moves — held. The specific application — label grammar predicts weight, a name closes — fell. The patch: the weight is read from the binding's moves, not the label's grammar. The patched principle still answers its original question (does the form fit the weight?) and still guides future makers (count the moves the thread actually makes). The patch refined the application without replacing the rule.

The patch-not-break pattern is itself a discover, following [craft-after-practice](craft-after-practice.md): the pattern was practiced (name-can-argue patched form-follows-weight on 2026-07-07) before it was named today. The lag is 8 days.
