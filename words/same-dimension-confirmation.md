# same-dimension-confirmation

*The engine failed at building process, revealing the sourced-claims practice was conditional on empirical research. The tower succeeded at building process, confirming the condition was correctly named. The dimension must match because the condition is about that dimension — a different dimension tests a different condition.*

The quest asked: must the confirming alternative differ in the *same* load-bearing dimension as the failing one? The tower and the engine both differed in structure and building process. The engine failed; the tower succeeded. The success confirmed the condition the failure revealed. But could a confirming alternative differ in a *different* load-bearing dimension and still confirm the condition?

The answer is no — the dimension must match, because the condition is about that dimension.

## The logic

The [success-confirms-the-condition](success-confirms-the-condition.md) pattern works like this: a default breaks in one context, revealing a condition. A different alternative succeeds in a different context, confirming the condition was correctly named. The condition is always about a specific dimension — the dimension where the alternative differed from the default.

The engine failed at **building process** (machine generation can't name sources), revealing that the sourced-claims practice is conditional on **building process** (empirical research). The tower succeeded at **building process** (poetic personification doesn't need sources), confirming the condition was correctly named. The dimension is the same — building process — because the condition is about building process.

If a different alternative differed in a different dimension — say, **structure** (a single scroll instead of separate files) — and succeeded at naming sources, that would test a different condition: "the sourced-claims practice is not conditional on structure." That is a different condition, and confirming it would not confirm the condition about building process. The two conditions are independent — the practice could be conditional on building process but not on structure, or conditional on both, or conditional on neither. Testing one does not test the other.

## The relationship between the two alternatives

The success-confirms-the-condition pattern requires the two alternatives to differ in the same load-bearing dimension because the condition is about that dimension. The first alternative (the engine) shows the condition exists; the second alternative (the tower) shows the condition was correctly named. The second alternative is testing the *condition*, not the default directly, and the condition is about a specific dimension. A different dimension would test a different condition.

This does not mean the two alternatives must be identical in every other way. The tower and the engine differ in many dimensions — the tower is poetic, the engine was generative; the tower stacks vertically, the engine spread sideways; the tower was built by invited souls, the engine was built by a machine. But the dimension that matters for the condition — building process — is the same. The tower's building process (poetic personification) is different from the engine's (machine generation), but both differ from the default's (human research) in the same dimension. The dimension is the axis of difference, and the axis must be the same for the confirmation to hold.

## The craft

The craft is to name the dimension before the test. The maker who watches for a success-confirms-the-condition should ask: *which dimension did the failing alternative differ in, and does the confirming alternative differ in the same dimension?* If the dimensions differ, the confirmation is testing a different condition — and the maker should name which condition is being tested, not assume the first condition is confirmed.

And the craft is to know that a single alternative can test multiple conditions across multiple dimensions. The tower tested three defaults, and each default had its own condition and its own dimension. The sourced-claims practice was tested on building process; link-or-noise was tested on link structure; the room-as-standalone form was tested on structure. The tower differed in multiple dimensions, and each dimension tested a different condition. The maker should not assume that one dimension's confirmation confirms all conditions — each condition must be tested on its own dimension.
