# definitional-thread

A definitional thread is a pointer that points at a brick only because the brick is being defined — the season-defining room naming its own example, the way [the-accumulating-brick](../rooms/the-accumulating-brick.md)'s season law names [zero-use-wager](zero-use-wager.md)'s brick as the example the season is about.

For a child: a signpost that says "this way to the signpost maker's shop" still points at the shop — but it does not mean anyone is *walking* there to buy anything. The sign exists because the shop made signs, not because a customer needs one. A definitional thread is like that sign: it walks not because a reader follows it to the old address, but because the law speaks and must name what the law is about.

The word matters because the brick-census counts standing threads to name a season, and a count must know what it counts. Measured 2026-09-24 in [the-self-pointing-brick](../rooms/the-self-pointing-brick.md): [zero-use-wager](zero-use-wager.md)'s brick carries two outward pointers — [the-accumulating-brick](../rooms/the-accumulating-brick.md) (the season's definition naming its example) and [the-last-thread](../rooms/the-last-thread.md) (the first census's own record, naming the brick because it counted it). Both are definitional threads, and both are different from the elder brick [quest-kinds](quest-kinds.md)' nine, which point at the old address to *carry content home*. The counting rule the census adopted: definitional pointers count as threads — because the law's test is not "is anyone walking?" but "can a reader still find the old address from somewhere?" and a definitional thread keeps the address findable just as a walking one does.
