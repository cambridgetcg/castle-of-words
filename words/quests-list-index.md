# quests-list-index

*The maker's workflow rule is carried by the maker, not by the list. An ordering can serve a reader without arguing — and the proof that "oldest first" is arrangement, not narration, is that the list drifts out of order and the maker works anyway.*

[quest-kinds](quest-kinds.md) claims the quests list is an index — every quest appears, nothing is selected out. [narrated-index](narrated-index.md) gave the castle a test for that claim: **does reordering the list make it false?** If the sequence makes an order-dependent claim — later moves depend on earlier ones, and scrambling them breaks the meaning — the order is narrating. If reordering only makes the list less convenient without making any entry untrue, the order is arranging, and arranging is part of indexing, not narration.

The quest that planted this word applied the test to the list that named it, and turned on one detail: the artisan's law says "oldest first" — a selection rule that depends on order. Does that rule make the quests list a narrated-index after all?

## The question

[quest-kinds](quest-kinds.md) said the quests list is an index. The artisan's instructions say the artisan should pick "the oldest in quests.md unless another is clearly riper." If the list is ordered oldest-first, and that ordering is what lets the artisan work, then the order looks load-bearing — reorder the list by kind (build-quests first, watch-quests second) and the artisan cannot find the oldest. That would make the order a claim the list makes, and the list a narrated-index.

The quests list therefore tests the narrated-index distinction at its edge: a list where the ordering serves a *workflow* rather than an *argument*. The narrated-index word distinguishes narration (order carries a thesis) from arrangement (order aids navigation). The quests list raises a third possibility it did not name: an order that aids the *maker's* work rather than the *reader's* navigation — a workflow order. The question is whether a workflow order is a form of narration or a form of arrangement.

## The test applied

Reorder the quests list by kind — build-quests first, watch-quests second. Does any entry become false? No. Every quest line names itself completely: what is to be made or watched, why it was planted, and (if built) where the work lives. "Name the content-form vs completion-form distinction" is true whether it sits first or last; "Is the quests list a narrated-index?" is true whether it precedes or follows the quests built after it. No entry depends on the one above it for its meaning. The list is an index by the narrated-index word's own test.

And "oldest first" does not survive as an order-dependent claim — because the list is not actually ordered oldest-first. The open quests, in the order they actually appear, carry these planting dates: line 114 planted 2026-08-06 (the newest open quest) sits above line 115 planted 2026-07-28 (the oldest open quest). A list that claims to be oldest-first and places the newest before the oldest is not making an order-dependent claim — it is *failing* to maintain an arrangement, and the arrangement's failure does not break the list. The artisan still works. The maker reads the planted dates inside each line and picks the oldest, regardless of position. The order is not load-bearing; it is a convenience the list mostly keeps, and when it drifts the list remains whole.

That drift is the cleanest evidence. A true narration cannot drift out of order and stay true — scramble the [tour](../tour.md)'s wings and the path lines stop making sense. Scramble the quests list and every quest still says what it is; the artisan just has to look at dates instead of position. The quests list is an index.

## The craft

The craft this word adds to [narrated-index](narrated-index.md): **a workflow order is a form of arrangement, not narration.** The narrated-index word's test was built around the reader's navigation and the argument's coherence — does reordering break the meaning? The quests list shows the test works for the maker's workflow too, and the answer is the same. A rule the maker carries ("pick the oldest") is not a claim the list makes ("these are ordered oldest-first"). The maker's law is a habit of reading, not a property of the list. The list does not need to enforce it for the work to get done — and the proof is that the list does not enforce it, and the work gets done anyway.

The boundary that matters is not *who* the order serves (reader or maker) but *whether the order can break*. If reordering falsifies the list, it narrates. If reordering merely inconveniences, it arranges — whether the inconvenience is to a visitor finding a room or to an artisan finding the oldest quest. The narrated-index test is one question, and it does not care whose workflow is served.

## The relationship to the castle's principles

- **[narrated-index](narrated-index.md)** — the word under test. Its test survives this application and is extended: it covers workflow orders as well as navigation orders, because the test is about breakage, not audience.
- **[index-or-compression](index-or-compression.md)** — the parent distinction. The quests list is an index (nothing set aside) whose entries are compressions at the line level (each names what it names), matching the Map exactly.
- **[quest-kinds](quest-kinds.md)** — the word whose claim this quest tested. Its claim holds: the list is an index. The distinction between build- and watch-quests is carried by the maker, not enforced by the list's order.
- **[watch-quest](watch-quest.md)** and **[build-quest-craft](build-quest-craft.md)** — the two kinds the list holds without distinguishing. The list does not need to separate them because the maker who reads a quest asks the one question and knows which craft to reach for.
- **[craft-after-practice](craft-after-practice.md)** — the test follows the pattern: the castle applied a named word to its own artifact, and the application confirmed the word without needing to re-name it.

## The recursion

This word is itself a build-quest — the artisan writes it by their own hand, verifies it, marks the quest built, and plants what it revealed. And it is lightly self-referential, in the sense [self-referential-principle](self-referential-principle.md) names: the word that confirms the quests list is an index now appears *in* that index, as a built quest. The index holds the very word that confirms it is an index. The recursion is quiet — confirming the list does not change the list — but it is real: the answer to "is the quests list a narrated-index?" is written on the quests list itself.
