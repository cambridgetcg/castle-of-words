# timestamp grain

*Two clocks photograph the same race; one shows the stride, the other shows only that the race was run.*

The size of the smallest time step a feed reports — a second, a day, a settlement date. Grain is a property of the *feed*, not of the movement: one ledger may know the second while the statement about it knows only the day.

For a child: if one friend says "the bell rang at four minutes past three" and the other says "it rang this afternoon," both are telling the truth — but the second friend's clock has bigger marks, and you cannot line two bells up unless both clocks use the same marks.

The word matters in the castle's accounting wing because [[movement-identity]]'s fallback hash begins with "timestamp-to-the-second." A feed whose grain is coarser than a second does not falsify the hash — it changes the hash's *definition* for that feed. The honest law the castle now keeps (settled 2026-09-03): name the grain, make it uniform across the feed, and hash the coarsened value — then false matches born of the coarser grain are counted as telemetry about that feed's weakness, never silently absorbed as truth. A timestamp-to-the-day can still deduplicate movements that are days apart; it cannot separate two movements in the same afternoon, and the honest gate holds the pair flagged until a second source — a transaction hash, a UTI, an end-to-end identification — decides. Coarsening *widens* the net only if the widening is hidden; named and uniform, it narrows what the hash claims to prove, which is exactly the claim's real strength.

Measured grains (read 2026-09-03 and 2026-09-04): Polymarket's data-api trade feed carries full second precision (observed live: unix seconds, e.g. 1788457446 = 2026-09-03T17:44:06Z; the newer TypeScript SDK reports `EpochMilliseconds`, so even milliseconds are available, but the seconds layer carries the movement's own identity — two trades in the same second are normal, so the timestamp alone never identifies; the tuple — timestamp, amount, currency, account-from, account-to — plus the feed's reporter-id, does). On-chain settlement is block-stamped by design: Polygon produces blocks roughly every two seconds, and every chain record of a movement shares its block's stamp — finer than a day, coarser than a unique beat, and the *block number*, not the wall clock, is the value the chain itself owns. Retail bank statement feeds are the coarsest of the three: posting dates to the day are the norm, intraday ordering often nothing more than a display order, and value dates belong to the bank's books rather than to the movement. Centralised exchanges are the finest: both Kraken's public trade tape and Coinbase Exchange's public trades endpoint (observed live 2026-09-04) carry microsecond-grain timestamps owned by the venue's match engine — Kraken as unix floats with 7 decimal digits, Coinbase as ISO 8601 with 6 decimal digits. The public tape and private fill report do not split: both report the same match engine's stamp for the same trade.

The banking rails, measured 2026-09-04 from their own documentation: camt.053 (the ISO 20022 bank-to-customer statement) carries booking and value dates as `<Dt>` — date-only — and the camt family's intraday sibling is a separate message (camt.052, replacing MT942), so the end-of-day statement is day-grained by design. The split, answered later the same day: camt.052 does carry entry-level time-of-day in a real deployment — Huntington's documented sample entry carries `<BookgDt><DtTm>2026-02-04T11:35:22Z</DtTm></BookgDt>` beside a date-only `<ValDt><Dt>` (the schema allows date-or-datetime; this bank chose datetime), so a bank offering both gives the observatory the movement's own posted instant from camt.052 and the law-recognised day from camt.053 — three messages, one grain each, the finest grain living in the message built for watching. Plaid's Transaction object splits the difference in an instructive way: `date` is date-only (`YYYY-MM-DD`), while `authorized_datetime` wears the ISO time shape `YYYY-MM-DDTHH:mm:ssZ` but is documented as coming "as provided by the institution" and possibly carrying **default time values (such as 00:00:00)** — a new pattern worth its own name: a *defaulted time*, a day wearing a time's coat, which a hash must treat as day-grain or it reads a mark the clock never made. TrueLayer's documented transaction example carries a second-grain `timestamp` (`2025-04-01T12:34:56Z`) — uncertain whose clock the second is.

And the collision arithmetic at card-feed volumes (settled 2026-09-04): with Visa's network processing 257.5 billion transactions in 2025, the average card sees under one transaction per day, so most (account, day) buckets hold a single movement and day-grain costs nothing at all; collisions need the same account-pair, same day, *same amount* — the rare two-identical-coffees case — and there the flag-and-hold gate already answers. Day-grain coarsening holds at card volumes because collisions stay a countable telemetry stream rather than a silent majority. The card rail's own clocks, settled later the same day: in the ISO 8583 dialect the networks run on, the movement's own instant is field DE 12 *Local Transaction Time* (hhmmss, **mandatory** in the authorization message) with DE 7 *Transmission Date and Time* beside it (MMDDhhmmss, mandatory), while settlement stays day-grained as DE 15 *Settlement Date* (MMDD) — second-grain at the terminal, day-grain on the books, in one message. uncertain: whether the networks' own clearing files (Visa BASE II, Mastercard's acquirer records) carry DE 12 onward — those file specs are not publicly published, so per-feed sampling still settles it.

uncertain: whether any specific retail feed the observatory will actually see exposes intraday posting times; the norm named above is the general practice, and each real feed must still be sampled before its grain can be named. Also uncertain: whether any specific private exchange fill report truncates or rounds its match-engine stamp, though both Kraken and Coinbase document the same float format for private fills as for the public tape, and the engine does not keep two clocks for the same trade.
