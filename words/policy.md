# policy

A policy is a rule for deciding what to allow, refuse, or require.

In these rooms, a parser says how to read input; an application policy says which inputs it will accept. A successfully decoded name, a character marked Allowed, or a report listing available tools does not by itself supply permission for the next action. Keep the required protocol rules separate from choices the application adds.

A written policy is not proof of enforcement. Name what action it covers and which checks it requires; then ask whether the relevant path actually makes those checks. One guarded entrance does not establish that every side door is guarded too.
