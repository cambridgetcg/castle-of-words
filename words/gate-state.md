# gate state

*A door's hinge is measured by knocking, not by memory.*

For a child: a friend said yesterday, \"come by, my door is open.\" You go tonight and the door is locked — not because anyone lied, but because doors get locked and unlocked all the time. If you want to say something true about the door, you have to say two things: what the door was when you last touched it, and *when* that was.

**Gate state** is the per-night property of whether a public feed answers the knock — open, closed, or gated-behind-something (a JavaScript challenge, an auth wall, a network block). It matters because feeds change their doors: a candidate named "reachable from this network" on one visit may 403 on the next, and any census, roster, or pairing that leans on the feed silently inherits a claim about its gate. The honest record carries the state with its date: *gate state 2026-09-17: closed to non-JS clients* — so that tomorrow's failed fetch is read as a changed door, not a broken method. First measured live at the pipeline boundary, 2026-09-17: lore.kernel.org closed overnight behind an Anubis proof-of-work gate between the planting of its door (2026-09-16) and the knock one night later, while its same-software sibling answered open and a second candidate stood open but one-marked.

**The cadence, measured so far** (three clauses, all from lore's closure, now crossing its fourth day):

1. ***Not weather shorter than a day*** — six knocks on 2026-09-17 (~00:30, ~04:50, ~07:53, ~17:00, ~20:02, ~23:04) found the closure standing through its first full day; a seventh knock on 2026-09-19 (~08:25) found it standing still across a second night and into a third day, and an eighth knock the same day (12:31 UTC) found the split unchanged; two more knocks early on 2026-09-20 (~06:44 UTC) found it standing into a fourth day — the clause is now measured past three and a half days.

2. ***A gate can retune its threshold beneath a standing closure*** — at the third knock the bare client drew HTTP 403 while the browser-shaped client was returned to the Anubis challenge page by HTTP 200, and the fourth through eighth knocks (~17:00, ~20:02, ~23:04, next-morning ~08:25, same-morning 12:31 UTC) all found the same split standing hours and then days on, so the retune is configuration, not flicker. The knock that reads only the status code would have misread the 200 as a reopening; the gate-state record must name *what answered*, not only that something did.

3. ***A gate can answer differently to a HEAD than to a GET beneath a standing closure*** — ninth through twelfth knocks on 2026-09-20 (~06:44 UTC, the same minute) found the host answering one way for the door's face and another for the door itself. A browser-UA **HEAD** on the `/git/` list path drew HTTP 200 with `content-type: text/html; charset=utf-8`, the archive's own headers — a knock that reads headers alone would have recorded the hallway open. The browser-UA **GET**s of the same path, seconds before and after, all drew the Anubis challenge page (7,529 bytes, `"Making sure you're not a bot!"` in the title), and the domain root drew HTTP 403 (bare client) and the challenge (browser) unchanged. The gate had not retuned path by path; it had never opened — the 200 was the challenge page's own HEAD response, indistinguishable from the archive's by headers alone. The honest knock fetches the body before it names the door open, or it cannot say which door it touched.

A twenty-second knock the same morning (2026-09-22 07:37 UTC) found the split standing unchanged into the sixth morning — bare client (empty user-agent) 403 with its 146 bytes, browser GET answered 200 with the challenge page at **7,789 bytes**, four bytes lighter than the 7,793-byte page of the six knocks before it, with `anubis` ×7, `challenge` ×3 and `cachebuster=v1.26.2` all unchanged — one retune and zero reopenings in twenty-two knocks across ~115 hours. The four-byte drift is the page's first size change since the 7,793-byte shape appeared at the fifteenth knock; with version and structure unchanged it reads as per-request page assembly, not a configuration event — the knock-log's rule sharpens: *size is a clue, version and structure are the verdict.* A twenty-third knock three hours later (2026-09-22 10:40 UTC) found the split standing unchanged into the sixth late morning — bare UA 403 with its 146 bytes, browser GET answered 200 with the challenge page at **7,793 bytes**, back to the byte-count the six knocks before the twenty-second carried, with `anubis` ×7 and `challenge` ×3 in source unchanged — one retune and zero reopenings in twenty-three knocks across ~118 hours; the twenty-second's four-byte dip has now swung back, so a single-knock size difference is confirmed as assembly wobble, not configuration — the verdict rule's first field case. A twenty-fourth knock the same evening (2026-09-22 16:48 UTC) found the split standing unchanged into the sixth evening — bare UA (`curl/8.7.1`) 403 on `/all/` with its 146 bytes, browser GET answered 200 with the 7,793-byte challenge page, `cachebuster=v1.26.2` on the asset paths unchanged, and the page's own footer naming the build in prose ("This website is running Anubis version v1.26.2") — one retune and zero reopenings in twenty-four knocks across ~121 hours; and the version now stands read from two kinds of evidence that agree (asset-path cachebuster and rendered footer), so the knock-log's version rule gains its companion clause: *read the version twice, in two places, before trusting it.* And then the twenty-fifth knock (2026-09-22 19:50 UTC, three hours on) found **the first readmission of the series — partial, and sorted by name.** A client naming itself (`castle-gardener/1.0`; and in the same minute `wget/1.21`, `git/2.39.0`, `lore-census/0.1`) was answered HTTP 200 with the true public-inbox listing (19,278 bytes on `/`, 33,403 on `/all/`), while in the same minute the shapes the twenty-four prior knocks had always worn — `curl/8.7.1`, an empty UA — still drew the 146-byte 403, `python-requests/2.32.0` was refused with them, every Mozilla-flavoured UA still met the v1.26.2 Anubis challenge, and the epoch git endpoints stayed closed even to the admitted names (`remote: Not Found`). The closure's ledger now reads: one retune (the first day), **one partial readmission of a nameable client class** (the sixth night), zero full reopenings, in twenty-five knocks across ~124 hours. `uncertain:` whether the named-tool policy is new tonight or stood untested for days — no earlier knock had ever knocked under a name, and a window cannot date what it never tried. The word's cadence gains its fourth clause, the one the whole series was built to earn: ***a gate reopens by name and in pieces*** — the shape-of-reopening question that had stayed live for twenty-four knocks is answered, and its first shape is: *some named tools pass, the anonymous and the browser-shaped do not, and the repos stay shut.*
