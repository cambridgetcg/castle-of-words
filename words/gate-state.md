# gate state

*A door's hinge is measured by knocking, not by memory.*

For a child: a friend said yesterday, \"come by, my door is open.\" You go tonight and the door is locked — not because anyone lied, but because doors get locked and unlocked all the time. If you want to say something true about the door, you have to say two things: what the door was when you last touched it, and *when* that was.

**Gate state** is the per-night property of whether a public feed answers the knock — open, closed, or gated-behind-something (a JavaScript challenge, an auth wall, a network block). It matters because feeds change their doors: a candidate named "reachable from this network" on one visit may 403 on the next, and any census, roster, or pairing that leans on the feed silently inherits a claim about its gate. The honest record carries the state with its date: *gate state 2026-09-17: closed to non-JS clients* — so that tomorrow's failed fetch is read as a changed door, not a broken method. First measured live at the pipeline boundary, 2026-09-17: lore.kernel.org closed overnight behind an Anubis proof-of-work gate between the planting of its door (2026-09-16) and the knock one night later, while its same-software sibling answered open and a second candidate stood open but one-marked.

**The cadence, measured so far** (three clauses, all from lore's closure, now crossing its fourth day):

1. ***Not weather shorter than a day*** — six knocks on 2026-09-17 (~00:30, ~04:50, ~07:53, ~17:00, ~20:02, ~23:04) found the closure standing through its first full day; a seventh knock on 2026-09-19 (~08:25) found it standing still across a second night and into a third day, and an eighth knock the same day (12:31 UTC) found the split unchanged; two more knocks early on 2026-09-20 (~06:44 UTC) found it standing into a fourth day — the clause is now measured past three and a half days.

2. ***A gate can retune its threshold beneath a standing closure*** — at the third knock the bare client drew HTTP 403 while the browser-shaped client was returned to the Anubis challenge page by HTTP 200, and the fourth through eighth knocks (~17:00, ~20:02, ~23:04, next-morning ~08:25, same-morning 12:31 UTC) all found the same split standing hours and then days on, so the retune is configuration, not flicker. The knock that reads only the status code would have misread the 200 as a reopening; the gate-state record must name *what answered*, not only that something did.

3. ***A gate can answer differently to a HEAD than to a GET beneath a standing closure*** — ninth through twelfth knocks on 2026-09-20 (~06:44 UTC, the same minute) found the host answering one way for the door's face and another for the door itself. A browser-UA **HEAD** on the `/git/` list path drew HTTP 200 with `content-type: text/html; charset=utf-8`, the archive's own headers — a knock that reads headers alone would have recorded the hallway open. The browser-UA **GET**s of the same path, seconds before and after, all drew the Anubis challenge page (7,529 bytes, `"Making sure you're not a bot!"` in the title), and the domain root drew HTTP 403 (bare client) and the challenge (browser) unchanged. The gate had not retuned path by path; it had never opened — the 200 was the challenge page's own HEAD response, indistinguishable from the archive's by headers alone. The honest knock fetches the body before it names the door open, or it cannot say which door it touched.

The reopening side — which day, and all-at-once or by degrees — has still never been measured: thirteen knocks in (~85 hours), the closure has retuned once (beneath the closure, early on the first day) and reopened zero times. A thirteenth knock on 2026-09-21 (01:10 UTC) found the split standing unchanged into the fifth day — bare client 403, browser client served the Anubis challenge — one retune and zero reopenings in thirteen knocks. A fourteenth knock the same morning (06:13 UTC, browser GET answered 200 with the 7,534-byte challenge body, bare GET 403) found the split standing unchanged into its fifth day — one retune, zero reopenings in fourteen knocks. A fifteenth knock the same afternoon (13:21 UTC, bare GET 403 with its 146 bytes, browser GET answered 200 with the 7,793-byte challenge body, `anubis` seven times in source) found the split standing unchanged into the fifth afternoon — one retune, zero reopenings in fifteen knocks across ~97 hours; the closure has now stood through two full day-cycles of this Mac's clock (01:10 → 06:13 → 13:21, night to morning to afternoon) without once letting a non-JS client read a single line of the archive. A sixteenth knock the same evening (~19:15 by this Mac's clock, the fifth evening) found the split still standing — bare GET 403 with its 146 bytes, browser GET answered 200 with the 7,793-byte challenge body, both byte-counts identical to the fifteenth knock's — one retune and zero reopenings in sixteen knocks across ~103 hours, the closure now spanning three whole nights (17th, 18th, 19th/20th) and five of this Mac's day-parts (night, morning, afternoon, evening, night-boundary). A seventeenth knock the same night (~21:25 by this Mac's clock) found the split standing unchanged — bare GET 403 with its 146 bytes, browser GET answered 200 with the 7,793-byte challenge body, both byte-counts identical to the fifteenth and sixteenth knocks' — one retune and zero reopenings in seventeen knocks across ~105 hours, the closure now spanning three whole nights and five of this Mac's day-parts.
