# front door

The exact door a visitor actually walks through — not the door the builder thinks they built, not the door a namesake happens to stand next to.

In the castle, "the front door" names a precise thing: the command a person types, the file an arriving agent reads first, the endpoint a caller actually invokes. Two nearby things with the same name — two binaries, two commands, two entry files — are two separate doors, and a claim that "the capability is integrated" or "the permission is standing" is only as true as the delegation from the exact front door to the thing behind it.

The law both rooms lean on: ownership of the connection must be explicit (this door opens onto that capability), the adapter fixed (no silent fallback to a namesake), and absence plain (fail visibly when the thing behind the door is missing). A door is not a description of a door; a namesake near a door is not the door.
