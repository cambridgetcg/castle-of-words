# narrated-index

*Every item appears — but does the order argue, or only arrange? An index can be well-ordered without narrating, and the difference is whether reordering breaks the list or merely shuffles it.*

[index-or-compression](index-or-compression.md) named the distinction between an index (everything appears, nothing set aside) and a compression (something chosen, something set aside). The [Map](../gate.md) is an index: every room gets its line, no room was picked to stand for another. But the Map's one-liners are themselves small compressions — each entry selects what to include from the room's full content — and their crafting builds something that *feels* like a story as you read down the list. The founding words give way to bridges, bridges to ease, ease to climbing, climbing to companionship, companionship to standards, standards to emotion, emotion to openness, openness to the copyright frontier. An arc is unmistakable. The question is whether that arc makes the Map a third form — every item present (index), each entry chosen (compression), the sequence carrying an argument (narration) — or whether it is an index whose thoughtful ordering only *resembles* narration.

The test is one question: **does the sequence make an order-dependent claim?** If the list would be *false* when reordered — if its meaning breaks because later moves depend on earlier ones — then the order is narrating. If the list would be *less convenient* when reordered but no less true — if every entry still correctly describes its room, just harder to navigate — then the order is arranging, and arranging is part of indexing, not narration.

The [tour](../tour.md) narrates. Its wing-to-wing "path" lines — *the founding words*, *a word is a brick — now lay them*, *ease feels like truth*, *and when ease runs out, climb*, *no one climbs alone*, *but who checks the echo?*, *a standard someone must teach* — are order-dependent claims. Scramble the wings and the paths break: *and when ease runs out, climb* makes no sense if the climbing rooms come first. The tour's sequence is load-bearing; reordering it does not degrade it, it incoheres it.

The Map arranges. Its ordering follows the tour's wing structure — the same conceptual arc, the same grouping — but it carries no path lines. No line in the Map says *and from here we turn to…*; no entry depends on the one above it for its meaning. Scramble the Map and every entry still describes its room correctly. The list becomes harder to navigate, less revealing of the castle's shape — but it does not become *false*. The Map's order is helpful, even crafted, but it is not load-bearing the way the tour's is. An index ordered well is still an index.

So the Map is not a narrated-index. The appearance of narration comes from two sources, neither of which is narration:

1. **Each entry compresses a room** — [index-or-compression](index-or-compression.md) already conceded this. But a compression *of* a room is not a compression *of* the castle, and the visible-thread principle asks whether the *list* compresses, not whether each *line* does. The entries are threaded at the line level (each selects what to include); the list is not threaded at the sequence level (no order-dependent claims).

2. **The ordering inherits the tour's arc** — the Map is arranged to follow the wing structure the tour authored. The tour narrated; the Map borrows the arrangement for navigability. The arc is real, but it is *authored by the tour* and *inherited by the Map*, not authored by the Map. Inheriting an order is not the same as making a claim with it.

The narrated-index remains a real form — just not one the castle has practiced. It would be a list where every item appears (index) but the sequence makes order-dependent claims (narration): a reading order that argues, where reordering breaks the argument even though no item is set aside. The form is conceivable: a chronicle that lists every event but orders them to make a causal claim, or a bibliography that names every source but sequences them to trace an idea's evolution. In each, nothing is omitted (index), each entry is crafted (compression at the line), and the order itself carries a thesis that could be wrong (narration at the sequence). The thread would live at the sequence level — the order-dependent claim — and the [visible-thread](visible-thread.md) principle would demand it be stated, not merely implied by arrangement.

Naming the form now is a wager on zero uses: the castle has no narrated-index, only an index that looked like one. But the distinction — does the order argue or arrange? — is load-bearing today, because it prevents the castle from mistaking good arrangement for narration. The [Map](../gate.md) is well-ordered, and its ordering is a craft (grouping by theme, following the castle's intellectual arc), but the craft is arrangement, not narration. Confusing the two would lead the castle to thread the Map's sequence with path lines it does not need — decoration on an index — or to claim the Map makes an argument it merely borrows. The distinction says: an index can reveal shape through ordering without becoming a narration, and that is not a failure to narrate but a different craft entirely.

And the distinction follows [second-use-reveals-form](second-use-reveals-form.md) in reverse. The narrated-index form has had *zero* uses — not even one. The Map looked like a first use, but the test (does reordering break it?) showed it was an index all along. A form with zero uses cannot be named as a craft, only defined as a possibility. What is named here is not the form but the test that distinguishes it from an index — and the test is load-bearing because the castle has an index that resembles the form closely enough to need the distinction drawn. The form itself waits for its first use; if it comes, the test will confirm it, and the name will follow.
