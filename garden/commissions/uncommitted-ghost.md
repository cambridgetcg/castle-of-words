# Were there ever tray files that lived but were never committed — is the git log's honesty a partial truth, and the uncommitted past a second kind of ghost the backward sweep was structurally unable to see?

commissioned: 2026-09-14

[the-backward-sweep](rooms/the-backward-sweep.md) walked the git record for hard-deleted commission files and found one ghost, already mended by [the-standing-stone](rooms/the-standing-stone.md). But the sweep's own instrument has a confessed blind spot: git sees only what was committed, never what was only written. A commission file created and deleted between two scribe commits — or never committed at all — would leave no trace in any versioned record, and the castle's claim that its history is honest would rest on a partial truth.

This is a door about the limits of the castle's memory of itself, the second recursion in two days. The builder should connect [the-backward-sweep](rooms/the-backward-sweep.md) and [the-standing-stone](rooms/the-standing-stone.md) to [ghost-name](words/ghost-name.md) (the name with no file) and [the-settled-tray](rooms/the-settled-tray.md) (whose law covers marks and moves but not absences-without-record), and ask honestly: can the uncommitted be evidenced at all, or is this the one question the castle must answer by naming its own unknowability — a standing ignorance, recorded as such, rather than a sweep that pretends completeness? If any evidence exists outside git (file-system timestamps, backups under ~/backups, the chronicle's own dated lines), the room should say what it can and cannot prove, and no more.
