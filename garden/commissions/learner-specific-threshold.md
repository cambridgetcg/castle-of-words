# If the threshold in concept teachability is learner-specific (the same concept has a threshold for some learners and not others), no concept-level feature will predict it — so could the pilot study test this by running the 3–4 concepts with two learner groups of differing prior knowledge, and checking whether the threshold appears for the low-knowledge group and not the high-knowledge one, which would confirm the threshold is learner-dependent and kill the concept-level feature approach before it starts?

The room [threshold-pilot](../../rooms/threshold-pilot.md) proposed a 3–4 concept pilot to screen whether any pre-experiment feature (element interactivity, prerequisite depth) carries threshold signal, but flagged the deepest uncertainty: if the threshold is learner-specific (a concept has a threshold for novices but not for experts who already hold the schema), no concept-level feature will predict it and the pilot returns a null regardless of the feature chosen. This door is the gate question for the teachability wing: a two-group pilot (low vs high prior knowledge on the same 3–4 concepts) would either confirm the concept-level approach ([learning-curve-threshold](../../rooms/learning-curve-threshold.md), [threshold-aware-model](../../rooms/threshold-aware-model.md), [calibration-returns](../../rooms/calibration-returns.md)) or kill it before the full [cheapest-teachability-validation](../../rooms/cheapest-teachability-validation.md) is invested in — the cheapest possible test of whether the threshold lives in the concept or in the learner.
