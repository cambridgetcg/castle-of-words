# the stale signpost

*A sign that was true when it was painted stays painted when it stops being true — and a wrong sign is worse than no sign, because the reader follows it with confidence.*

What gathers here: the settlement of whether a beside-signpost is itself a promised shape that the census must read against the machinery it describes, or whether that reading loops forever into descriptions of descriptions.

---

**The door.** [the-folds-honest-bound](the-folds-honest-bound.md) placed the accumulation gate's honesty on its beside-signpost — the vault's README names the archive law and points to RECOVERY.md. The open door pressed the next stone: a signpost is itself a declaring document that ages. The README says "Retention counts only pairs whose checksum and gzip-tar listing verify" — if the script's true behavior drifted, the README would stand as a *stale promise*, legible-looking and wrong. Is the beside-signpost itself a promised shape — should the census read each signpost against the machinery it describes, one glance per signpost per census — or does that loop forever, each layer of description needing a description to check it by?

**The walk, 2026-09-12.** Yes on both counts, settled on the grounds this visit.

**First: Map lines do drift.** A Map line is written when a room is young — most of the 611 were stamped at the build date — while rooms are extended later ("added to 2026-09-02", "updated 2026-08-01"). The wording of a line can quietly fall behind the room's own second paragraph. The drift is real in shape even when the Map still passes a `castle check`, because the check resolves links, not meanings. The line "the craft of building an accounting product" still resolves to the room, but if the room's later walk added three more duties the line silently understates.

**Second: the census owes the Map's own lines the same stale-promise check the vault's README now owes.** This room answered the archive-side twin above: the beside-signpost is a promised shape, and the census reads it against the machinery it describes once per census, by date and by drift, never by re-execution. The Map line is exactly a beside-signpost — it stands beside the room's own door and names what the room holds. The same law covers it. The check is the same too: one glance at two timestamps and one declared date — the Map line's implied "as of" (the gate's own last touch) against the room's own last touch — plus `castle check`'s link-resolution as the drift probe.

What this visit's walk found, as the standing example: gate.md last moved 2026-09-12 02:23; zero rooms stand newer. The Map's 611 lines are, this census, all fresher than the rooms they describe — no stale promises to catch. The duty is owed regardless; today it ran and came back empty, which is the visit the law hopes for. **The original walk, 2026-09-12, for the door as it was first asked** (the vault's README and RECOVERY.md): Three readings on the grounds:

**First: the ground-floor description is a promised shape, and the table must carry it.** [the-table-of-promised-shapes](the-table-of-promised-shapes.md) already gathers eleven promised shapes from RECOVERY.md and the vault README. Those shapes are written in one place and name what another place must hold — but the README itself is a place that names what the script must hold. The README is a promised shape too, and its own row in the table reads: the vault's README names the archive law and the strict-seal checklist, and the census reads the README against the script's actual clauses, one glance per census. The reading does not loop; it stops at the ground floor because the ground floor is a file the gardener can read in one window, while the script is machinery the gardener is told never to touch. The loop is bounded by the table's own law: only shapes written down on the grounds count, and the shape that checks the checker is declared on the grounds as plainly as the shape it checks.

**Second: the check is by date and by drift, not by re-execution.** The gardener cannot run `seed-vault.sh` to see whether it still honors the strict-seal checklist; that would be the machinery checking itself. What the gardener can check is the signpost's *currency*: the README's own dates, the file's mtime against the script's mtime, and the promised shape's reviewed-on date. [self-sealed-prior](../words/self-sealed-prior.md) settled that a declared shape carries its own shelf-life, and [defaulted-time](../words/defaulted-time.md) settled that a declared expectation is honest only while it is regularly reassessed. The same law covers the signpost: a README whose reviewed-on date is older than the script's last change is a stale promise waiting to be caught. The mark does not prove the script drifted; it proves the reader's confidence has outlived its warrant. One glance at two timestamps and one declared date is the whole test.

**Third: the loop terminates because the castle's laws are plain-text and bounded.** Each layer of description lives in plain markdown, one room or one brick, capped at a child's sentence before depth. The census reads the signpost against the machinery; the machinery's honesty is kept by its own boundedness (fail-closed, append-only, one job). There is no fourth layer because the castle does not build a description of the description of the description — the word file's own small-to-survive law forbids it. The infinite regress is refused by the house style: a promise that needed a promise to check it would be a promise too heavy to carry.

**The shape named, once:** the beside-signpost is a promised shape, and the census reads it against the machinery it describes once per census — by date and by drift, never by re-execution — until the ground floor, where the reading stops because plain text is the floor the castle stands on.
