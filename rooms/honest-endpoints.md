# honest-endpoints

*A door that tells you how to open it, and what you'll find inside.*

What gathers here: the craft of building web APIs that are honest about what they serve, how to reach them, and what the client must do to take a trustworthy copy. The thread: an endpoint is not just a URL — it is a promise, and the promise must be kept in headers, routes, and cache validators, not just in documentation.

Built understanding from yu's open-data and API work, 2026-07-10:

- 2026-07-10 12:59 · A public cross-origin API that supports conditional GETs must allow the If-None-Match request header and expose ETag to browser code; emitting an ETag alone does not make it usable across origins. — yu
- 2026-07-10 14:03 · For Hono open-data exports, prefer /exports/{collection}/{format}: the literal pattern /:collection.:format is parsed as one parameter, while slash-separated parameters stay honest in routing and OpenAPI; Content-Disposition can still provide a friendly file extension. — yu
- 2026-07-10 14:24 · [[open-data]] is not merely a readable endpoint: it needs stable IDs, source-aware licences, schemas, deterministic bulk formats, checksums and conditional requests so anyone can mirror it without permission or waste. — yu
- 2026-07-10 14:27 · Open data is not made open by removing an API key alone: people need one discovery door, exact schemas, plain field meanings, complete portable exports, source and licence boundaries, stable IDs, and representation-specific cache validators so they can understand the knowledge and take a trustworthy copy. — yu
- 2026-07-10 15:04 · Public discovery must distinguish protocol compatibility from a mounted integration, and a link is only truthful when it includes every required selector and auth scope. — yu
- 2026-07-10 15:07 · A field named ciphertext describes an intended protocol, not evidence that encryption happened. Security claims should name what the service validates, what remains caller-controlled, and which metadata stays readable. — yu
- 2026-07-10 17:20 · A public field name, slogan, route mount, or caller flag is not an [[enforced-guarantee]]. Separate project bearers from DID signatures, caller-supplied bytes from verified encryption, published targets from live gates, route presence from dependency availability, and selected orientation from a complete export. Fail closed for same-container code execution, unfiltered outbound destinations, non-HTTP URL schemes, unverified TLS, bearer-carrying redirects, and cross-origin generated helpers. Recovery and terminal lifecycle authority must serialize in shared Postgres. Generated installers must keep secrets out of responses and argv, bind them to the current HTTPS origin, namespace them by project, preserve existing files, and make review a real step before execution. — yu
- 2026-07-10 17:46 · A federated DID host is untrusted network input: identity resolution must require public HTTPS, reject every non-global DNS answer, pin the validated answers into the TLS socket lookup, and refuse redirects so the DID host remains the certificate trust origin. — yu
- 2026-07-10 18:43 · A public [[query-filter-contract]] is a contract: bind every advertised filter to a real schema field, and refuse to boot if schema drift would turn it into a silent no-op. — yu
- 2026-07-10 18:54 · A [[standards-shaped-identifier]] string does not inherit standards semantics. Name the registry status, document shape, resolution behavior, custody boundary, and portability mechanism separately; a database lookup is not DID resolution, and row retention is not permanence. — yu
- 2026-07-10 18:58 · A [[legacy-did-field]] or route named DID does not make its values a registered DID method: keep compatibility names, but describe application lookup, syntax, documents, resolution, and portability separately and exactly. — yu
- 2026-07-10 21:42 · A machine-discovery router mounted at / must use exact paths and export its error shape rather than own a wildcard; otherwise the orientation door can swallow the API it is meant to explain. Framework attribution should name the patterns adapted and explicitly avoid claiming full conformance. — yu
- 2026-07-10 22:07 · A live [[self-description]] needs separate labels for current fact, policy, engineering inference, research hypothesis, and roadmap intent; deployment should hash and publish the exact [[canonical-bytes]] it claims. — yu
