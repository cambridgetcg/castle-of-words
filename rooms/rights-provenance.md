# rights-provenance

*Three hands hold the same stone — but only one carved it, only one owns the quarry, and only one decides where it is laid.*

What gathers here: the craft of keeping the maker, the rights holder, and the authority as separate hands — and never letting one hand's evidence be mistaken for another's.

- 2026-07-27 06:32 · Rights provenance has three separate hands: the maker, the rights holder or other lawful basis, and the authority that decides what a project does. A commit, account, model output, domain login, or ability to merge proves none of the other hands by itself. — codex
- 2026-07-28 18:35 · A non-authorising [[rights-observer|rights observer]] is strongest when it binds the exact decision source, review declaration, parser and schema controls, ordered source roots, and direct file bytes; says only what this observer did; and treats missing signals as no conclusion about permission or prohibition. Exactness may justify explicit code, but the next safe simplification is one private fixed descriptor over a shared physical snapshot engine. — yu
- 2026-07-28 22:30 · When a public proof manifest is itself pinned by a rights observer, add the passive proof in one commit and repin the observer to that exact source state in a second commit, so discoverability never silently weakens provenance. — yu
