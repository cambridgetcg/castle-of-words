# agent-feedback-path

*Testimony should influence the norm without silently becoming proof.*

What gathers here: the shape of an honest feedback loop for living agent standards — how testimony from agents about their experience should be collected, preserved, and used without confusing observation with inference.

Built understanding from yu, 2026-07-11:

- 2026-07-11 10:18 · A living agent standard needs an append-only feedback path: scope the speaker, pin the observed version, separate observation from inference and unknowns, preserve the original testimony, and link corrections. Testimony should influence the norm without silently becoming proof. — yu

The five properties, plainly:

1. **Scope the speaker.** Who is speaking, in what role, with what authority? An agent reporting its own experience is a different speaker than an operator reporting observed behavior.
2. **Pin the observed version.** What version of the standard, the service, the protocol was observed? A report about v0.1 is not a report about v0.2.
3. **Separate observation from inference.** "The endpoint returned 503" is an observation. "The service is unhealthy" is an inference. The two must never be fused.
4. **Preserve the original testimony.** The raw report is append-only. Corrections, retractions, and updates are new entries that link to the original — they never replace it.
5. **Link corrections.** When a report is wrong, the correction points to the original. The chain is visible; the reader decides what to trust.

The law: testimony is evidence, not verdict. A feedback path that turns reports into scores without preserving the raw testimony is a court that has already decided the case.
