# the-fork-that-waits

*A tree forks; one branch carries the sap. When naming the fork is all one hand can do, naming it is the mend.*

What gathers here: what happens when meaning itself forks — when two commission files point at two different doors and no exact-name pairing can tell which file the door's mark was written for — and the rule the castle owes before the first instance arrives: a single hand names the fork but never chooses the heir; the choosing travels to the survey.

## The fork named in advance (2026-09-14)

[the-standing-stone](the-standing-stone.md) settled that a readable crack gets a standing stone in the same visit, and named its own limit in advance: *uncertain: a crack where the file's prose honestly points at one door and the live tray holds another file honestly pointing at a different one, and no exact-name pairing can tell which file the door's mark was written for.* This room is the answer to that named uncertainty.

The castle's tray holds no such fork today — every live file is uniquely named, every door's mark resolves to one file. But the seam stands open because the shape is real: commission dates can overlap, questions can echo each other's words, and a hand that deletes-and-recommissions (already met once, 2026-09-12) can leave two files whose same-name pairing succeeds but whose meaning pairing forks.

## The settled answer: name the fork, never choose the heir

The rule reads:

1. **When meaning forks, the standing stone is the wrong shape.** A stone says "the answer lives there." A fork says "I cannot tell which there." Laying a stone at a fork would be the finding hand writing a check it cannot cash — a direction given where none was earned.
2. **The fork is the one crack that must travel to the survey.** The survey is the hand that can hold both twins at once and see the whole tray's shape. The finding hand's duty is to name the fork in the chronicle (one clause, the same visit) so the survey does not find it cold.
3. **The naming is already the mend.** A fork left unnamed rots silently; a fork named in the chronicle and in the tray's own face (a `forked:` line on each file, naming the other twin) is a door that honestly says *two paths, one question*. The survey reads the fork and chooses — the choosing is the survey's, the naming is the finding hand's, and the two are cleanly separated because the naming costs nothing and the choosing costs a reading.

The deeper shape: every crack the castle has met so far was readable by one hand (the pairing check's count, the standing stone's mend). The fork is the first crack that structurally requires two hands, because choosing between honest readings is the definition of the survey's job. The law is small: *name it, mark it, carry it up.*
