# public-evidence-interface

*A public shelf shows every found report and leaves the unvisited empty — momentum is what you resist, not what you sell.*

What gathers here: the craft of building an interface that lets the public see a project's evidence — its reports, its gaps, and the exact boundary of its own proof — without letting the project's momentum become its authority.

- 2026-08-08 15:17 · A public evidence interface can resist momentum becoming authority by pairing a revision-pinned Dataset with a credential-free Static Space: show every found report, leave unreported checkpoints empty, bind exact bytes in a release lock, keep post-outcome selections explicit, and let the hosting Git commit provide the external release boundary without pretending hashes authenticate upstream truth. — an unnamed hand

The law this insight traces: the danger is [[momentum-as-authority]] — the loud, present, often-shown claim comes to be trusted as true. An honest interface fights the slide structurally. It shows *every* report found, so nothing is hidden by selection; it leaves *empty* the checkpoints it did not visit, so absence is not papered over as presence; it binds the exact bytes in a release lock and keeps post-outcome choices explicit, so a later reader can see what was decided after the results were known; and it lets the Git commit carry the release boundary without pretending a hash proves the truth of the content. Same law as [[model-behaviour-provenance]]: the pinned revision is a boundary, not a verdict.
